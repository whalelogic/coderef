Concurrency Patterns — Deep Dive

Advanced, production-proven patterns focusing on lifecycle, backpressure, observability, and failure modes.

Pattern What It Solves Canonical Example Notes / Production Tips
Structured concurrency (errgroup + context) Tie goroutines to a parent scope and propagate errors and cancellation 
g, ctx := errgroup.WithContext(ctx)\ng.Go(func(){ return work(ctx) })\nif err := g.Wait(); err != nil { ... }
 Use for request-scoped or job-scoped operations; ensures no leaked workers. Prefer errgroup for simple fan-out with error handling.
Bounded work queue + backpressure Prevent uncontrolled memory growth when producers are faster than consumers 
jobs := make(chan Job, N)\nfor i:=0;i
Expose queue depth metrics; use circuit-breakers when queue consistently full.
Semaphore pattern Limit concurrency for ad-hoc critical sections without full pool 
sem := make(chan struct{}, N)\nacquire := func(){ sem<-struct{}{} }\nrelease := func(){ <-sem }
 Combine with context-aware select to avoid deadlocks on shutdown.
Pipeline stages with bounded parallelism Composable ETL with per-stage concurrency and flow-control 
in := make(chan A)\nstage := func(in<-chan A, out chan<-B){\n for v := range in { out<-process(v) }\n close(out)\n}\n
 Be explicit about who closes channels; use WaitGroup for graceful shutdown when stages share workers.
Retry with exponential backoff + jitter Robust retries while avoiding thundering herd 
for i:=0;i
Prefer \"full jitter\" (random between 0 and cap) or decorrelated jitter. Cap maximum backoff and consider circuit breaker integration.
Fan-out/fan-in with ordered aggregation Parallelize CPU-bound tasks while preserving input order 
type res struct{ idx int; val T; err error }\nout := make(chan res)\nfor i,v := range inputs{ i,v:=i,v; go func(){ out<-process(i,v) }() }\nresults := make([]T, len(inputs))\nfor range inputs{ r := <-out; results[r.idx]=r.val }\n
 Use sequence numbers to restore order. Buffer results to avoid blocking workers on slow downstream consumers.
Cooperative cancellation inside long-running CPU loops Allow long tasks to be preempted cleanly 
for i:=0;i
Chunk CPU work and check ctx periodically. Fine-grained cancellation points balance responsiveness vs overhead.
Graceful shutdown: drain then close Complete inflight work while rejecting new requests 
draining := true\n// stop accepting new\nclose(acceptCh)\n// wait for inflight to finish via WaitGroup\nwg.Wait()\n
 Expose health endpoint that reports \"draining\" state. Use readiness probes in orchestrators.
Leader election (distributed) Ensure a single instance performs background tasks 
lock := NewEtcdLock(\"job-name\")\nif lock.TryLock(ctx) { runLeaderTasks(ctx) }\n
 Use TTL-based leases and renewals. Handle split-brain by ensuring work is idempotent or uses external coordination.
Bulkhead isolation Limit blast radius of failing downstreams 
semaphores per downstream; queues per downstream
 Combine with circuit breakers and capacity shedding for robust resilience.

System Programming & Process Control — Deep Dive

Advanced OS and process controls used in tooling, sandboxes, and platform daemons.

Technique Why It Matters Canonical Example Notes / Gotchas
Process groups and job control Terminate whole process trees reliably 
cmd.SysProcAttr = &syscall.SysProcAttr{Setpgid: true}\n// kill - signal to -pid to target group\nsyscall.Kill(-pid, syscall.SIGTERM)\n
 Unix-only; be careful with PID sign semantics. Use in supervisors to clean children.
PTY for interactive children Run TUI apps and capture full terminal I/O 
f, err := pty.Start(cmd)\nio.Copy(os.Stdout, f)\n
 Handle terminal resize and raw mode. Be careful with codecs and line discipline.
ExtraFiles for fd passing Handshake file descriptors between parent and child (e.g., sockets) 
cmd.ExtraFiles = []*os.File{listenerFile}\n
 Child receives fds starting at fd 3; document protocol and order.
Credential switching Run subprocesses with least privilege 
cmd.SysProcAttr.Credential = &syscall.Credential{Uid: uid, Gid: gid}\n
 Requires privilege to lower or set credentials. Use in daemons spawning user jobs.
Signal forwarding and orchestrated shutdown Make process behave correctly in containers and init systems 
sigc := make(chan os.Signal,1)\nsignal.Notify(sigc, syscall.SIGTERM)\n<-sigc\ncancel()\n
 Don't forward SIGKILL. Ensure children are reaped (Wait) or use subreaper.
Reaping & subreapers Prevent zombie accumulation in nested container environments 
prctl(PR_SET_CHILD_SUBREAPER, 1)\n
 Use x/sys/unix and test in containerized setups. Kernel-dependent behavior.
Namespace isolation (unshare) Lightweight sandboxing for builds/tests 
syscall.Unshare(syscall.CLONE_NEWNS | ...)\n
 Requires privileges; mounts and capabilities must be handled carefully.
Files descriptor lifetimes & Close-on-exec Avoid leaking fds into child processes 
fd.Fd(); syscall.CloseOnExec(fdint)
 Use O_CLOEXEC where possible and check third-party libraries leaking fds.
High-performance logging to file without allocations Reduce GC pressure in logging hot-paths 
use mmaped buffers or preallocated ring buffers and background flusher
 Complex; prefer well-tested libraries unless you need extreme throughput.

Reflection, Metaprogramming & Code Generation — Deep Dive

Techniques for large-codebase automation, generation, and tooling.

Technique Why It Matters Example Notes
AST transforms (go/ast + go/parser) Automate code changes reliably preserving semantics 
fset := token.NewFileSet()\nnode, _ := parser.ParseFile(fset, path, nil, parser.ParseComments)\nast.Inspect(node, func(n ast.Node) bool{ ... })\n
 Preserve comments and formatting with go/printer or go/format. Make transforms idempotent.
go/analysis for custom linters Enforce team invariants at compile/CI time 
analysis.Analyzer{ Name: \"nofoo\", Run: func(pass *analysis.Pass) (interface{}, error){ ... } }\n
 Integrate with golangci-lint; avoid expensive analyzers in pre-commit hooks.
go:generate + templates Generate repetitive code from small templates 
//go:generate go run ./cmd/gen\n
 Keep generators idempotent and fast. Check generated output into VCS if stable.
Zero-allocation codecs via reflect + unsafe Extreme performance for serialization 
use field offsets and write to []byte directly
 Brittle across versions and architectures; maintain tests and fallbacks.
Stringer / codegen for enums Readable and efficient enum printing 
//go:generate stringer -type=State\n
 Generated String() reduces human errors; keep in repo or generated at build.
Programmatic go list and module analysis Build repo-aware tools and dependency checks 
go list -json ./... | jq
 Useful to find version skew and replace directives.
Plugins for runtime extension Hot-loadable features in controlled environments 
p, _ := plugin.Open(\"mod.so\")\nsym, _ := p.Lookup(\"Make\")\n
 Linux-only and version-sensitive; prefer RPC for portability.

Performance-critical Go — Deep Dive

Low-level performance techniques for CPU, memory, and latency-sensitive systems.

Technique Why It Matters Example Notes / Caveats
Escape analysis & stack allocation Avoid unnecessary heap allocations 
go build -gcflags=-m\nrefactor to keep objects stack-allocated
 Small refactors can change escape behavior; validate with -m.
Struct layout for cache friendliness Improve memory density and cache performance 
group 64-bit fields, then 32-bit fields
 Measure with benchmarks; layout depends on architecture.
Read-copy-update (RCU) via atomic swaps Lock-free reads with copy-on-write updates 
new := &T{...}; atomic.StorePointer(&ptr, unsafe.Pointer(new))\nold := (*T)(atomic.LoadPointer(&ptr))\n
 Writers pay copy cost; readers get cheap access. Memory grows until old copies GC'd.
Shard counters & per-cpu structures Eliminate contention on global counters 
shards := make([]uint64, N)\nidx := runtime_procPin() % N; atomic.AddUint64(&shards[idx], 1)\n
 Sum across shards when reading; choose N as small multiple of CPU cores.
Atomic.Value for config swapping Low-latency, contention-free reads with safe updates 
var v atomic.Value\nv.Store(cfg)\ncfg := v.Load().(*Config)\n
 Store full value; updates must replace entire object to avoid races.
pprof-driven optimization Target real hotspots instead of guessing 
go test -bench . -benchmem; pprof -http=:8080 cpu.prof
 Always profile in production-like workload for meaningful results.
Inline heuristics for hot paths Reduce call overhead by enabling compiler inlining 
keep functions small; avoid interface calls in hot loops
 Check inlining with -m; restructure to help compiler inline.
Minimize allocations in serialization Reduce GC churn across RPC boundaries 
use preallocated buffers, io.WriteTo patterns
 Consider binary formats and buffer pooling with sync.Pool.
