Structs in Go

Structs are Go's primary mechanism for creating custom data types that group related data together. Unlike object-oriented languages with classes, Go uses structs combined with methods to achieve similar functionality in a simpler, more explicit way. Structs are the foundation for building complex, maintainable applications in Go.

Basic Struct Definition

A struct is defined using the type keyword followed by the struct name and field declarations. Fields can be of any type, including other structs, pointers, slices, maps, and interfaces. 

package main

import "fmt"

// Basic struct definition
type Person struct {
    Name string
    Age  int
}

// Struct with multiple field types
type Employee struct {
    ID        int
    FirstName string
    LastName  string
    Email     string
    Salary    float64
    IsActive  bool
}

// Struct with embedded types
type Address struct {
    Street  string
    City    string
    State   string
    ZipCode string
}

type Contact struct {
    Name    string
    Phone   string
    Address Address  // Nested struct
}

func main() {
    // Create struct with field names (recommended)
    p1 := Person{
        Name: "Alice",
        Age:  30,
    }
    fmt.Printf("%+v\n", p1)  // %+v prints field names

    // Create struct with positional values (not recommended)
    p2 := Person{"Bob", 25}
    fmt.Println(p2)

    // Zero value: all fields get their zero values
    var p3 Person
    fmt.Printf("Zero value: %+v\n", p3)  // {Name: Age:0}

    // Accessing and modifying fields
    p1.Name = "Alice Smith"
    p1.Age++
    fmt.Printf("Updated: %+v\n", p1)

    // Nested struct
    contact := Contact{
        Name:  "Charlie",
        Phone: "555-1234",
        Address: Address{
            Street:  "123 Main St",
            City:    "Boston",
            State:   "MA",
            ZipCode: "02101",
        },
    }
    fmt.Printf("Lives in %s, %s\n", contact.Address.City, contact.Address.State)
}

Field Visibility: Struct fields starting with uppercase letters are exported (public) and accessible from other packages. Lowercase fields are unexported (private) and only accessible within the same package.

Pointers to Structs

Pointers to structs are extremely common in Go. They allow you to pass structs efficiently without copying all their data, and enable methods to modify the original struct. Go automatically dereferences struct pointers, making them convenient to use. 

package main

import "fmt"

type Rectangle struct {
    Width  float64
    Height float64
}

func main() {
    // Create a pointer to a struct using &
    rect1 := &Rectangle{Width: 10, Height: 5}
    
    // Go automatically dereferences, no need for (*rect1).Width
    fmt.Printf("Width: %.2f, Height: %.2f\n", rect1.Width, rect1.Height)
    
    // Modify through pointer
    rect1.Width = 20
    fmt.Printf("New width: %.2f\n", rect1.Width)
    
    // Create struct value, then take address
    rect2 := Rectangle{Width: 15, Height: 8}
    rectPtr := &rect2
    rectPtr.Height = 10
    fmt.Printf("rect2 after modification: %+v\n", rect2)
    
    // Using new() allocates memory and returns pointer
    rect3 := new(Rectangle)  // All fields are zero values
    rect3.Width = 30
    rect3.Height = 15
    fmt.Printf("rect3: %+v\n", rect3)
    
    // Passing by pointer vs by value
    modifyByValue(rect2)
    fmt.Printf("After modifyByValue: %+v\n", rect2)  // Unchanged
    
    modifyByPointer(&rect2)
    fmt.Printf("After modifyByPointer: %+v\n", rect2)  // Modified
}

// Takes a copy of the struct (expensive for large structs)
func modifyByValue(r Rectangle) {
    r.Width = 100  // Only modifies the copy
}

// Takes a pointer (efficient, can modify original)
func modifyByPointer(r *Rectangle) {
    r.Width = 100  // Modifies the original
}

Performance Tip: For structs larger than a few fields, always use pointers to avoid expensive copies. This is especially important when passing structs to functions or storing them in slices.

Methods on Structs

Methods are functions with a special receiver argument that appears between func and the method name. Methods can have either value receivers or pointer receivers, each with different semantics. 

package main

import (
    "fmt"
    "math"
)

type Circle struct {
    X      float64
    Y      float64
    Radius float64
}

// Value receiver - receives a copy of the struct
func (c Circle) Area() float64 {
    return math.Pi * c.Radius * c.Radius
}

// Value receiver - cannot modify original
func (c Circle) ScaleValue(factor float64) {
    c.Radius *= factor  // Only modifies the copy
}

// Pointer receiver - can modify the original struct
func (c *Circle) Scale(factor float64) {
    c.Radius *= factor  // Modifies the original
}

// Pointer receiver for efficiency (large struct)
func (c *Circle) Move(dx, dy float64) {
    c.X += dx
    c.Y += dy
}

// Method that returns a new instance
func (c Circle) Translated(dx, dy float64) Circle {
    return Circle{
        X:      c.X + dx,
        Y:      c.Y + dy,
        Radius: c.Radius,
    }
}

func main() {
    circle := Circle{X: 0, Y: 0, Radius: 5}
    
    // Call method with value receiver
    area := circle.Area()
    fmt.Printf("Area: %.2f\n", area)
    
    // This doesn't modify the original
    circle.ScaleValue(2)
    fmt.Printf("After ScaleValue: %+v\n", circle)  // Radius still 5
    
    // This modifies the original
    circle.Scale(2)
    fmt.Printf("After Scale: %+v\n", circle)  // Radius now 10
    
    // Move the circle
    circle.Move(10, 15)
    fmt.Printf("After Move: %+v\n", circle)
    
    // Get a new translated circle
    newCircle := circle.Translated(5, 5)
    fmt.Printf("Original: %+v\n", circle)
    fmt.Printf("Translated: %+v\n", newCircle)
}

Receiver Choice: Use pointer receivers when the method needs to modify the receiver, when the struct is large (avoid copying), or when some methods already use pointer receivers (for consistency). Use value receivers for small, immutable structs.

Struct Embedding and Composition

Go doesn't have inheritance, but it has something more flexible: embedding. When you embed a struct, all its fields and methods become part of the outer struct. This enables composition patterns that are often clearer than traditional inheritance. 

package main

import "fmt"

// Base types
type Engine struct {
    Horsepower int
    Type       string
}

func (e Engine) Start() {
    fmt.Printf("Starting %s engine (%d HP)\n", e.Type, e.Horsepower)
}

func (e Engine) Stop() {
    fmt.Println("Engine stopped")
}

type GPS struct {
    Lat  float64
    Long float64
}

func (g GPS) CurrentLocation() string {
    return fmt.Sprintf("%.4f, %.4f", g.Lat, g.Long)
}

// Embedded struct - inherits fields and methods
type Car struct {
    Engine          // Anonymous field - embedding
    GPS             // Embed GPS
    Make   string
    Model  string
    Year   int
}

// Car can have its own methods too
func (c Car) Info() string {
    return fmt.Sprintf("%d %s %s", c.Year, c.Make, c.Model)
}

// Method can be overridden
func (c Car) Start() {
    fmt.Printf("Starting %s...\n", c.Info())
    c.Engine.Start()  // Call embedded method explicitly
    fmt.Println("Car is ready to drive")
}

// Nested vs Anonymous embedding
type Vehicle struct {
    engine Engine  // Named field - NOT embedding
}

func main() {
    car := Car{
        Engine: Engine{
            Horsepower: 300,
            Type:       "V6",
        },
        GPS: GPS{
            Lat:  42.3601,
            Long: -71.0589,
        },
        Make:  "Toyota",
        Model: "Camry",
        Year:  2024,
    }
    
    // Can access embedded fields directly
    fmt.Printf("Horsepower: %d\n", car.Horsepower)
    fmt.Printf("Location: %s\n", car.CurrentLocation())
    
    // Can access embedded fields explicitly
    fmt.Printf("Engine type: %s\n", car.Engine.Type)
    
    // Call methods
    car.Start()  // Calls Car's Start method
    car.Stop()   // Calls Engine's Stop method (promoted)
    
    fmt.Println(car.Info())
}

Embedding vs Composition: Embedding (anonymous fields) promotes the embedded type's methods to the outer type. Named fields require explicit access. Choose embedding when you want the outer type to "act like" the embedded type.

Struct Tags and Reflection

Struct tags are metadata attached to struct fields, commonly used for JSON/XML encoding, database mapping, and validation. They're accessed via reflection and are essential for working with APIs and databases. 

package main

import (
    "encoding/json"
    "fmt"
)

// Struct with tags for JSON marshaling
type User struct {
    ID        int    `json:"id"`
    Username  string `json:"username"`
    Email     string `json:"email"`
    Password  string `json:"-"`  // Never marshal this field
    FirstName string `json:"first_name,omitempty"`  // Omit if empty
    LastName  string `json:"last_name,omitempty"`
    IsActive  bool   `json:"is_active"`
    Metadata  map[string]interface{} `json:"metadata,omitempty"`
}

// Multiple tags for different purposes
type Product struct {
    ID          int     `json:"id" db:"product_id" validate:"required"`
    Name        string  `json:"name" db:"product_name" validate:"required,min=3"`
    Price       float64 `json:"price" db:"price" validate:"required,gt=0"`
    Description string  `json:"description,omitempty" db:"description"`
}

func main() {
    user := User{
        ID:        1,
        Username:  "alice",
        Email:     "alice@example.com",
        Password:  "secret123",  // Won't appear in JSON
        FirstName: "Alice",
        IsActive:  true,
    }
    
    // Marshal to JSON
    jsonData, err := json.MarshalIndent(user, "", "  ")
    if err != nil {
        fmt.Println("Error:", err)
        return
    }
    fmt.Println("JSON output:")
    fmt.Println(string(jsonData))
    
    // Unmarshal from JSON
    jsonInput := `{
        "id": 2,
        "username": "bob",
        "email": "bob@example.com",
        "first_name": "Bob",
        "last_name": "Smith",
        "is_active": false
    }`
    
    var newUser User
    err = json.Unmarshal([]byte(jsonInput), &newUser)
    if err != nil {
        fmt.Println("Error:", err)
        return
    }
    fmt.Printf("\nUnmarshaled user: %+v\n", newUser)
}

Common Tag Conventions: json:"name" for JSON field names, json:"-" to skip a field, json:"name,omitempty" to omit zero values, db:"column" for database column mapping, validate:"rules" for validation libraries.

Constructor Functions and Validation

Go doesn't have constructors, but the convention is to create New functions that initialize structs with default values and perform validation. This ensures structs are always in a valid state. 

package main

import (
    "errors"
    "fmt"
    "strings"
)

type Account struct {
    id       int  // Unexported - can't be set directly
    username string
    email    string
    balance  float64
}

// Constructor with validation
func NewAccount(username, email string) (*Account, error) {
    // Validate input
    if len(username) < 3 {
        return nil, errors.New("username must be at least 3 characters")
    }
    if !strings.Contains(email, "@") {
        return nil, errors.New("invalid email address")
    }
    
    // Return initialized struct
    return &Account{
        id:       generateID(),  // Internal ID generation
        username: username,
        email:    email,
        balance:  0.0,  // Default balance
    }, nil
}

// Constructor with options pattern
type ServerConfig struct {
    Host    string
    Port    int
    Timeout int
    Debug   bool
}

func NewServerConfig() *ServerConfig {
    return &ServerConfig{
        Host:    "localhost",
        Port:    8080,
        Timeout: 30,
        Debug:   false,
    }
}

// Option function type
type ServerOption func(*ServerConfig)

// Option functions
func WithHost(host string) ServerOption {
    return func(c *ServerConfig) {
        c.Host = host
    }
}

func WithPort(port int) ServerOption {
    return func(c *ServerConfig) {
        c.Port = port
    }
}

func WithDebug() ServerOption {
    return func(c *ServerConfig) {
        c.Debug = true
    }
}

// Constructor with options
func NewServer(opts ...ServerOption) *ServerConfig {
    config := NewServerConfig()  // Start with defaults
    
    for _, opt := range opts {
        opt(config)  // Apply each option
    }
    
    return config
}

// Getters for unexported fields
func (a *Account) Username() string {
    return a.username
}

func (a *Account) Balance() float64 {
    return a.balance
}

// Methods that modify state safely
func (a *Account) Deposit(amount float64) error {
    if amount <= 0 {
        return errors.New("deposit amount must be positive")
    }
    a.balance += amount
    return nil
}

func (a *Account) Withdraw(amount float64) error {
    if amount <= 0 {
        return errors.New("withdrawal amount must be positive")
    }
    if amount > a.balance {
        return errors.New("insufficient funds")
    }
    a.balance -= amount
    return nil
}

var idCounter = 0

func generateID() int {
    idCounter++
    return idCounter
}

func main() {
    // Using constructor
    account, err := NewAccount("alice", "alice@example.com")
    if err != nil {
        fmt.Println("Error:", err)
        return
    }
    
    account.Deposit(100.50)
    account.Withdraw(25.00)
    fmt.Printf("Account: %s, Balance: $%.2f\n", 
        account.Username(), account.Balance())
    
    // Using options pattern
    server := NewServer(
        WithHost("0.0.0.0"),
        WithPort(3000),
        WithDebug(),
    )
    fmt.Printf("Server config: %+v\n", server)
}

Best Practices: Use constructor functions to enforce invariants, hide implementation details with unexported fields, provide getters/setters for controlled access, and use the options pattern for structs with many configuration parameters.

Comparing and Copying Structs

Structs can be compared with == if all their fields are comparable. Understanding struct comparison and copying behavior is important for correct program logic. 

package main

import "fmt"

type Point struct {
    X, Y int
}

type Person struct {
    Name string
    Age  int
}

type Data struct {
    ID     int
    Values []int  // Slice is not comparable
}

func main() {
    // Struct comparison
    p1 := Point{X: 1, Y: 2}
    p2 := Point{X: 1, Y: 2}
    p3 := Point{X: 2, Y: 3}
    
    fmt.Println(p1 == p2)  // true - same values
    fmt.Println(p1 == p3)  // false - different values
    
    // Copying structs (makes a full copy)
    person1 := Person{Name: "Alice", Age: 30}
    person2 := person1  // Copy
    person2.Age = 31
    fmt.Printf("person1: %+v\n", person1)  // Age still 30
    fmt.Printf("person2: %+v\n", person2)  // Age is 31
    
    // Pointer to struct (shares data)
    ptr1 := &Person{Name: "Bob", Age: 25}
    ptr2 := ptr1  // Copy pointer, not struct
    ptr2.Age = 26
    fmt.Printf("ptr1: %+v\n", ptr1)  // Age is 26 (shared)
    fmt.Printf("ptr2: %+v\n", ptr2)  // Age is 26 (shared)
    
    // Uncomment to see compiler error:
    // d1 := Data{ID: 1, Values: []int{1, 2}}
    // d2 := Data{ID: 1, Values: []int{1, 2}}
    // fmt.Println(d1 == d2)  // ERROR: invalid operation
}

Comparability Rules: Structs are comparable if all fields are comparable types (no slices, maps, or functions). Use custom comparison functions for structs with non-comparable fields. Always copy by pointer when you want to share data between variables.

Best Practices

  • Use descriptive names: Struct and field names should clearly indicate their purpose.
  • Keep structs focused: Each struct should represent a single concept or entity.
  • Prefer composition: Use embedding to build complex types from simpler ones.
  • Validate in constructors: Always validate input and return errors from New functions.
  • Use pointer receivers: For most methods, especially if the struct is large or needs modification.
  • Hide implementation details: Use unexported fields and provide getters/setters.
  • Document exported types: Add comments explaining the struct's purpose and usage.
  • Use struct tags appropriately: Leverage tags for JSON, database mapping, and validation.
