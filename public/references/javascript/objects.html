JavaScript Objects

An in-depth guide to object creation, properties, methods, prototypes, classes, and modern object-oriented patterns in JavaScript.

Objects are the most fundamental building blocks in JavaScript. An object is a collection of key-value pairs, where keys are strings (or Symbols) and values can be anything: strings, numbers, booleans, arrays, or even other objects and functions. Understanding objects is essential for mastering JavaScript.

1. Creating Objects

There are several ways to create objects in JavaScript, each with its own use case.

Object Literal

This is the simplest and most common way to create an object. It's concise and readable, making it ideal for most situations.

// Object literal
const person = {
    name: "Alice",
    age: 30,
    greet() { // ES6 method shorthand
        return `Hello, I'm ${this.name}`;
    }
};
console.log(person.greet()); // "Hello, I'm Alice"

Constructor Functions

Before ES6 classes, constructor functions were the standard way to create objects of the same type, simulating a "class" structure. The new keyword creates a new object, sets this to that object, and returns it.

// Constructor function
function Person(name, age) {
    this.name = name;
    this.age = age;
}
const alice = new Person("Alice", 30);
console.log(alice.name); // "Alice"

ES6 Classes

ES6 introduced the class keyword, which provides a cleaner and more modern syntax for creating objects and handling inheritance. It is "syntactic sugar" over JavaScript's existing prototype-based inheritance.

// ES6 Class
class User {
    constructor(name) {
        this.name = name;
    }
    greet() {
        return `Hi, I'm ${this.name}`;
    }
}
const user = new User("Bob");
console.log(user.greet()); // "Hi, I'm Bob"

2. Property Access & Manipulation

You can access, add, or modify object properties using dot notation or bracket notation.

const obj = { name: "Alice", age: 30 };

// Dot notation (for valid identifiers)
console.log(obj.name); // "Alice"

// Bracket notation (for dynamic keys or invalid identifiers)
console.log(obj["age"]); // 30
const key = "name";
console.log(obj[key]); // "Alice"

// Adding properties
obj.city = "NYC";
obj["country"] = "USA";

// Deleting properties
delete obj.age;

// Checking for property existence
console.log("name" in obj);        // true
console.log(obj.hasOwnProperty("name")); // true
Best Practice: Use dot notation whenever possible as it is more readable. Use bracket notation when the property name is stored in a variable or is not a valid identifier (e.g., contains spaces or special characters).

3. Object Methods and `this`

Methods are functions stored as object properties. The this keyword inside a method refers to the object the method is called on. However, arrow functions behave differently, inheriting this from the parent scope.

const person = {
    name: "Alice",
    age: 30,
    
    // Method shorthand (correct 'this' binding)
    greet() {
        return `Hello, I'm ${this.name}`;
    },
    
    // Arrow function (incorrect 'this' binding for methods)
    getName: () => this.name // 'this' will be the global object, not 'person'
};

console.log(person.greet()); // "Hello, I'm Alice"
console.log(person.getName()); // undefined

Getters and Setters

Getters and setters allow you to define custom behavior for reading and writing properties.

const user = {
    firstName: "John",
    lastName: "Doe",
    
    get fullName() {
        return `${this.firstName} ${this.lastName}`;
    },
    
    set fullName(value) {
        [this.firstName, this.lastName] = value.split(" ");
    }
};
console.log(user.fullName);    // "John Doe"
user.fullName = "Jane Smith";  // Calls the setter
console.log(user.firstName);   // "Jane"

4. Object Iteration

There are several ways to loop over an object's properties.

const person = { name: "Alice", age: 30, city: "NYC" };

// for...in loop (iterates over all enumerable properties, including inherited ones)
for (let key in person) {
    if (person.hasOwnProperty(key)) { // Good practice to check for own properties
        console.log(key, person[key]);
    }
}

// Object.keys() (returns an array of own property keys)
Object.keys(person).forEach(key => {
    console.log(key, person[key]);
});

// Object.values() (returns an array of own property values)
Object.values(person).forEach(value => {
    console.log(value);
});

// Object.entries() (returns an array of [key, value] pairs for own properties)
Object.entries(person).forEach(([key, value]) => {
    console.log(`${key}: ${value}`);
});

5. Object Copying & Merging

Copying objects correctly is crucial to avoid unintended side effects.

Shallow Copy

A shallow copy creates a new object, but if the original object contains other objects, only the references to those objects are copied.

const original = { a: 1, b: { c: 2 } };

// Shallow copy with spread syntax (...)
const copy = { ...original };
copy.a = 100; // Does not affect original
copy.b.c = 99; // This MUTATES the original object!

console.log(original.b.c); // 99

Deep Copy

A deep copy creates a new object and recursively copies all nested objects, so there are no shared references.

const original = { a: 1, b: { c: 2 } };

// The modern, recommended way for deep copying
const deepCopy = structuredClone(original);
deepCopy.b.c = 99; // Does not affect original

console.log(original.b.c); // 2

// A common but limited older method
const deepCopyJSON = JSON.parse(JSON.stringify(original));
Key Insight: The structuredClone() global function is the modern and robust way to create deep copies of objects. It can handle complex data types that JSON.parse(JSON.stringify()) cannot, such as Dates, RegExps, and Maps.

6. Object Destructuring (ES6)

Destructuring provides a convenient way to extract properties from objects and bind them to variables.

const person = { name: "Alice", age: 30, city: "NYC" };

// Basic destructuring
const { name, age } = person;
console.log(name); // "Alice"

// Renaming variables
const { name: personName } = person;
console.log(personName); // "Alice"

// Default values
const { country = "USA" } = person;
console.log(country); // "USA"

// Rest properties
const { name: n, ...rest } = person;
console.log(rest); // { age: 30, city: "NYC" }

// Function parameter destructuring
function greet({ name, age }) {
    return `Hello ${name}, you are ${age}`;
}
console.log(greet(person)); // "Hello Alice, you are 30"

7. Prototypes & Inheritance

JavaScript uses a prototype-based inheritance model. Every object has a private property which holds a link to another object called its prototype. That prototype object has a prototype of its own, and so on, until an object is reached with null as its prototype. This is known as the prototype chain.

// ES6 Class inheritance provides a cleaner syntax for this
class Animal {
    constructor(name) {
        this.name = name;
    }
    speak() {
        return `${this.name} makes a sound`;
    }
}

class Dog extends Animal {
    speak() {
        // super.speak() could be used to call the parent method
        return `${this.name} barks`;
    }
}

const buddy = new Dog("Buddy");
console.log(buddy.speak()); // "Buddy barks"
console.log(buddy instanceof Dog);    // true
console.log(buddy instanceof Animal); // true

8. Modern Object Patterns

Optional Chaining (?.)

Safely access nested properties without having to write long chains of checks for null or undefined values.

const user = { profile: { name: "Alice" } };
console.log(user?.profile?.name);      // "Alice"
console.log(user?.address?.city);      // undefined (no error is thrown)

Nullish Coalescing (??)

Provides a default value for a variable that is null or undefined, without falling back on falsy values like 0, false, or an empty string "".

const config = { timeout: 0 };
// The '||' operator would incorrectly use 5000 because 0 is falsy
const timeoutWithOr = config.timeout || 5000; // 5000
// The '??' operator correctly uses 0
const timeoutWithCoalesce = config.timeout ?? 5000; // 0

9. Best Practices

  • Use const for objects to prevent accidental reassignment of the object reference.
  • Use object literals and classes for creating objects, as they are the most readable and standard approaches.
  • Use destructuring to make your code more concise and readable, especially when working with large objects or function parameters.
  • Use the spread syntax (...) for shallow copies and merging, and structuredClone() for deep copies.
  • Leverage optional chaining (?.) and nullish coalescing (??) to write safer and more concise code.
  • Keep objects focused on a single responsibility to improve modularity and maintainability.
