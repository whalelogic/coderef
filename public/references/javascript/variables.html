Variables in JavaScript

A deep dive into ES6+ variable declarations, scoping, hoisting, and modern best practices.

JavaScript is a dynamically typed language, meaning you don't have to specify the type of a variable when you declare it. The type is determined at runtime. This offers flexibility but also requires a solid understanding of how variables work to write clean, bug-free, and maintainable code.

The Three Keywords: var, let, and const

Modern JavaScript (ES6 and beyond) provides three keywords for declaring variables: let, const, and the older var. Each has different scoping rules and behaviors that are critical to understand.

var: The Legacy Keyword

Before ES6 (2015), var was the only way to declare variables. It is function-scoped, meaning it is only confined to the function it was declared in, not to blocks like if statements or for loops. It also has some quirks, like hoisting, which can lead to unexpected behavior.

Best Practice: It is strongly recommended to avoid var in modern codebases in favor of let and const to prevent common bugs related to scope and hoisting. 
// 'var' is function-scoped, not block-scoped.
function testVar() {
    var x = 10;
    if (true) {
        var y = 20; // 'y' is accessible throughout the function
        console.log(x); // 10
    }
    console.log(y); // 20 (leaks out of the if-block)
}
testVar();

// 'var' is hoisted and initialized with 'undefined'.
console.log(hoistedVar); // undefined (not a ReferenceError)
var hoistedVar = "I'm hoisted";

// 'var' can be redeclared in the same scope, which can cause bugs.
var count = 5;
var count = 10; // No error, 'count' is simply overwritten.
console.log(count); // 10

Key Insight: The function-scoping of var is a common source of bugs. Variables can "leak" out of blocks, and redeclaring a variable doesn't produce an error, making it easy to accidentally overwrite variables. This can lead to unpredictable behavior in larger applications.

let: The Modern, Re-assignable Variable

let is the modern replacement for var. It is block-scoped, meaning it's confined to the nearest curly braces {} (e.g., an if block or a for loop). This provides more predictable behavior and helps prevent bugs. 

// 'let' is block-scoped.
let a = 1;
if (true) {
    let b = 2; // 'b' only exists within this block
    console.log(a); // 1 (can access outer scope)
    console.log(b); // 2
}
// console.log(b); // ReferenceError: b is not defined

// 'let' cannot be redeclared in the same scope.
let name = "Alice";
// let name = "Bob"; // SyntaxError: Identifier 'name' has already been declared

// It can be reassigned.
name = "Bob"; // This is fine
console.log(name); // "Bob"

// Temporal Dead Zone (TDZ)
// Accessing 'let' before declaration results in an error.
// console.log(tdzVar); // ReferenceError: Cannot access 'tdzVar' before initialization
let tdzVar = "Now initialized";

Best Practice: Use let when you know a variable's value will need to change, such as in a loop counter or for a value that gets updated over time. Its block-scoping makes it a safer and more predictable choice than var.

const: The Modern, Constant Reference

const is also block-scoped, but it creates a read-only reference to a value. This means the variable cannot be reassigned. For primitive types (like numbers and strings), this makes the value immutable. For objects and arrays, the reference is immutable, but the contents of the object or array can still be changed. 

// 'const' must be initialized at declaration.
const PI = 3.14159;
// const GRAVITY; // SyntaxError: Missing initializer in const declaration

// The reference cannot be reassigned.
// PI = 3.14; // TypeError: Assignment to constant variable.

// For objects and arrays, the content can be changed.
const user = { name: "Alice" };
user.name = "Bob"; // This is allowed
user.age = 30;     // This is also allowed
console.log(user); // { name: "Bob", age: 30 }

// user = { name: "Charlie" }; // TypeError: Assignment to constant variable.

const numbers = [1, 2, 3];
numbers.push(4); // OK
numbers[0] = 99; // OK
// numbers = [4, 5, 6]; // TypeError

// To make an object truly immutable, use Object.freeze().
const config = Object.freeze({
    API_URL: "https://api.example.com",
    TIMEOUT: 5000
});
// config.TIMEOUT = 3000; // Fails silently (or throws TypeError in strict mode)

Best Practice: Prefer const by default for all variable declarations. This makes your code easier to reason about, as you know the variable's assignment won't change. Only use let if you specifically need to reassign the variable. This is a core principle of modern JavaScript development.

Scoping Rules Explained

JavaScript has three main types of scope: global, function, and block. Understanding scope is key to avoiding bugs and writing modular code.

// Global Scope: Accessible from anywhere in the code.
const globalVar = "I'm global";

function outerFunction() {
    // Function Scope: Accessible only within this function.
    const functionVar = "I'm in the function";

    if (true) {
        // Block Scope: Accessible only within this block.
        let blockVar = "I'm in the block";
        console.log(globalVar);   // Accessible
        console.log(functionVar); // Accessible
        console.log(blockVar);    // Accessible
    }
    // console.log(blockVar); // ReferenceError
}
outerFunction();
// console.log(functionVar); // ReferenceError

Hoisting: A JavaScript Quirk

Hoisting is JavaScript's behavior of moving declarations to the top of their scope before code execution. However, the behavior differs between var, let, and const.

  • var declarations are hoisted and initialized with undefined.
  • let and const declarations are hoisted but not initialized. They are in a "temporal dead zone" (TDZ) from the start of the block until the declaration is encountered.
// 'var' is hoisted and initialized as undefined.
console.log(myVar); // undefined
var myVar = 5;

// 'let' and 'const' are hoisted but not initialized.
// console.log(myLet); // ReferenceError: Cannot access 'myLet' before initialization
let myLet = 10;

// Function declarations are fully hoisted (body and all).
sayHello(); // "Hello!"
function sayHello() {
    console.log("Hello!");
}

// Function expressions are not hoisted.
// sayGoodbye(); // TypeError: sayGoodbye is not a function
var sayGoodbye = function() {
    console.log("Goodbye!");
};

Destructuring Assignment

A powerful feature of modern JavaScript, destructuring allows you to unpack values from arrays or properties from objects into distinct variables. This can make your code more concise and readable.

// Array Destructuring
const colors = ["red", "green", "blue"];
const [firstColor, secondColor] = colors;
console.log(firstColor); // "red"

// Object Destructuring
const person = { name: "John Doe", age: 42 };
const { name, age } = person;
console.log(name); // "John Doe"

// Renaming variables
const { name: personName } = person;
console.log(personName); // "John Doe"

// Default values
const { country = "USA" } = person;
console.log(country); // "USA"

Key Takeaways & Best Practices

  • Prefer const by default. This ensures that you don't accidentally reassign variables.
  • Use let only for variables that need to be reassigned, like loop counters.
  • Avoid var completely in modern JavaScript to avoid its weird quirks with scoping and hoisting.
  • Keep variables in the smallest scope possible. This makes your code easier to manage and reduces the chance of naming conflicts.
  • Use descriptive names to make your code self-documenting.
