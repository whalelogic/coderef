Ruby: Symbols vs. Strings

Understanding the difference between two of Ruby's most common data types.

In Ruby, both Strings and Symbols can be used to represent text, but they have fundamental differences in their behavior and purpose. Understanding when to use each is key to writing efficient and idiomatic Ruby code.

1. Strings: Mutable Text

A String is a mutable sequence of characters. This means that the content of a string can be changed after it is created. Strings are used for handling textual data that you expect to read, display, or manipulate.

# String creation
greeting = "Hello"
puts "Initial object ID: #{greeting.object_id}"

# Strings are mutable, so you can change them in-place
greeting << ", World!" # Appending to the string
puts greeting #=> "Hello, World!"
puts "Object ID after mutation: #{greeting.object_id}" # The object ID is the same

# Every string literal creates a new object in memory
puts "hello".object_id #=> (some object id)
puts "hello".object_id #=> (a different object id)
Use Strings for:
  • User input and output.
  • Any text that needs to be modified or manipulated.
  • Reading data from files, databases, or APIs.

2. Symbols: Immutable Identifiers

A Symbol is an immutable, reusable identifier. It's best to think of a symbol as a label or a name. Once a symbol is created, it exists exactly once in memory. Every time you refer to that symbol, you are referring to the same object.

# Symbol creation starts with a colon
status = :pending
puts "Object ID for :pending: #{status.object_id}"

# Symbols are immutable
# status << "_new" # This would raise a NoMethodError

# The same symbol always refers to the same object
puts :pending.object_id #=> (same object id as above)
puts :pending.object_id #=> (same object id as above)
Use Symbols for:
  • Hash keys. This is the most common use case. It's faster and more memory-efficient than using strings.
  • Method names, arguments, or other identifiers passed around your program.
  • Representing a fixed set of states (e.g., :active, :inactive, :pending).

3. The Main Differences Summarized

Strings

  • Mutable: Can be changed after creation.
  • Inefficient as Hash Keys: A new object is created for each string key.
  • Purpose: For representing and manipulating textual data.

Symbols

  • Immutable: Cannot be changed.
  • Efficient as Hash Keys: Only one object exists for any given symbol.
  • Purpose: For use as identifiers, labels, or states.

4. Practical Example: Hash Keys

Using symbols as hash keys is the idiomatic standard in modern Ruby. It is more performant because the same symbol key doesn't need to be re-allocated in memory every time it's used.

# The modern, preferred way using symbols as keys
person_symbol_keys = { name: "Alice", age: 30 }

# The older "hash rocket" syntax with strings as keys
person_string_keys = { "name" => "Alice", "age" => 30 }

# Accessing is similar, but the underlying key is different
puts person_symbol_keys[:name] #=> "Alice"
puts person_string_keys["name"] #=> "Alice"

5. Converting Between Types

You can easily convert between strings and symbols.

# String to Symbol
my_string = "status"
my_symbol = my_string.to_sym # or .intern
puts my_symbol #=> :status

# Symbol to String
my_symbol = :status
my_string = my_symbol.to_s # or .id2name
puts my_string #=> "status"

# A common use case is converting string keys in a hash to symbol keys
string_hash = { "name" => "Bob", "age" => 42 }
symbol_hash = string_hash.transform_keys(&:to_sym)
puts symbol_hash #=> {:name=>"Bob", :age=>42}
