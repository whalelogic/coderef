Ruby Classes and Objects

An introduction to Ruby's object-oriented features, including classes, inheritance, and modules.

In Ruby, everything is an object. A class is a blueprint from which individual objects are created. Classes define the attributes (data) and methods (behavior) that their objects will have.

1. Defining a Class

You define a class using the class keyword. The initialize method is a special method, the constructor, which is called when a new object is created with .new.

class Person
  # The constructor, called when Person.new is invoked.
  def initialize(name, age)
    # Instance variables hold data for a specific object.
    @name = name
    @age = age
  end
  
  # An instance method, which defines the object's behavior.
  def introduce
    "Hi, I'm #{@name} and I'm #{@age} years old."
  end
end

# Create a new object (an instance of the Person class)
person = Person.new("Alice", 30)
puts person.introduce #=> Hi, I'm Alice and I'm 30 years old.

2. Attribute Accessors

To allow access to instance variables from outside the object, Ruby provides convenient "accessor" methods. Instead of writing getter and setter methods manually, you can use these shortcuts.

class Person
  # attr_reader: Creates a getter method.
  attr_reader :id
  
  # attr_writer: Creates a setter method.
  attr_writer :secret
  
  # attr_accessor: Creates both a getter and a setter method.
  attr_accessor :name, :age
  
  def initialize(name, age)
    @name = name
    @age = age
    @id = rand(1000) # A random ID for this instance
  end
end

person = Person.new("Bob", 25)

# Use the getter created by attr_accessor
puts person.name #=> "Bob"

# Use the setter created by attr_accessor
person.age = 26
puts person.age #=> 26

# The ID can only be read
puts person.id #=> (some random number)
# person.id = 123 #=> NoMethodError: undefined method `id='

# The secret can only be written
person.secret = "shhh"
# puts person.secret #=> NoMethodError: undefined method `secret'

3. Class Variables and Methods

Class variables (@@) are shared among all instances of a class. Class methods (defined with self.) belong to the class itself, not to individual objects.

class Counter
  # A class variable, shared by all instances.
  @@total_instances = 0
  
  def initialize
    # Increment the class variable every time a new object is created.
    @@total_instances += 1
  end
  
  # A class method, which can be called on the class directly.
  def self.total_instances
    @@total_instances
  end
end

Counter.new
Counter.new
puts Counter.total_instances #=> 2
Best Practice: Be cautious with class variables (@@). Their state is shared across all instances and even subclasses, which can lead to unexpected behavior. For most cases, instance variables are a safer choice.

4. Inheritance

Inheritance allows a class to inherit behavior from a parent class (or "superclass"). This is a fundamental way to establish relationships between objects and reuse code.

class Animal
  def initialize(name)
    @name = name
  end
  
  def speak
    "#{@name} makes a sound."
  end
end

# Dog inherits from Animal using the '<' symbol.
class Dog < Animal
  # We can override the parent's method to provide a more specific implementation.
  def speak
    "#{@name} barks!"
  end
  
  def fetch
    "#{@name} is fetching."
  end
end

buddy = Dog.new("Buddy")
puts buddy.speak #=> "Buddy barks!"
puts buddy.fetch #=> "Buddy is fetching."

The `super` Keyword

The super keyword allows you to call a method from the parent class within the child class. It's often used in initialize to extend the parent's constructor rather than replacing it.

class Car < Vehicle
  def initialize(wheels, brand)
    # `super` calls the `initialize` method of the Vehicle class.
    super(wheels)
    @brand = brand
  end
  
  def info
    # `super` here calls the `info` method of the Vehicle class.
    super + " and is a #{@brand}"
  end
end

car = Car.new(4, "Toyota")
puts car.info #=> "This vehicle has 4 wheels and is a Toyota"

5. Modules and Mixins

Modules provide a way to group related methods, constants, and classes. One of their most powerful uses is as "mixins" to share functionality between classes without using inheritance.

# A module containing methods related to flying.
module Flyable
  def fly
    "I'm flying!"
  end
end

# A module for swimming behavior.
module Swimmable
  def swim
    "I'm swimming!"
  end
end

# By including the modules, the Duck class gains their methods.
class Duck
  include Flyable
  include Swimmable
end

class Fish
  include Swimmable
end

duck = Duck.new
puts duck.fly   #=> "I'm flying!"
puts duck.swim  #=> "I'm swimming!"

fish = Fish.new
puts fish.swim  #=> "I'm swimming!"
# fish.fly #=> NoMethodError
Key Insight: This "mixin" pattern is a cornerstone of Ruby. It allows for a form of multiple inheritance and is preferred over complex class hierarchies. It promotes writing small, reusable chunks of behavior.

6. Access Control

Ruby provides three levels of access control for methods: public, protected, and private.

  • Public: Can be called by anyone. This is the default.
  • Protected: Can be called by other objects of the same class or subclasses.
  • Private: Can only be called within the object itself (you cannot specify a receiver like other.private_method).
class BankAccount
  def initialize(balance)
    @balance = balance
  end
  
  # This is a public method.
  def balance
    @balance
  end
  
  # All methods defined after this are private.
  private
  
  def secret_code
    "1234"
  end
end

account = BankAccount.new(100)
puts account.balance #=> 100
# puts account.secret_code #=> NoMethodError: private method `secret_code' called
