Python Context Managers

Master resource management with the `with` statement, custom context managers, and the `contextlib` module.

A context manager is an object that defines a temporary context for a block of code. They are most commonly used with the with statement and are brilliant for ensuring that resources are properly acquired and, more importantly, released, even if errors occur.

1. The `with` Statement

The with statement simplifies resource management by guaranteeing that cleanup code is executed. The most common example is working with files.

# The old, verbose, and risky way
file = open('example.txt', 'w')
try:
    file.write('Hello, World!')
finally:
    # This cleanup code must always be run, even if an error occurs in the try block.
    file.close()

# The modern, Pythonic way using a context manager
with open('example.txt', 'w') as file:
    file.write('Hello, World!')
# The file is automatically closed when the 'with' block is exited.
# This is safer, cleaner, and less error-prone.
Key Insight: The with statement provides a reliable way to manage resources. It ensures that cleanup logic (like closing a file or releasing a lock) is always executed, preventing resource leaks.

2. Creating a Class-Based Context Manager

You can create your own context managers by defining a class with two special "dunder" methods: __enter__ and __exit__.

  • __enter__: Called when entering the with block. Its return value is bound to the variable after as.
  • __exit__: Called when exiting the with block. It receives information about any exceptions that occurred and performs the cleanup.
class DatabaseConnection:
    def __init__(self, host, port):
        self.host = host
        self.port = port
        self.connection = None
    
    def __enter__(self):
        """Acquire the resource and return it."""
        print(f"Connecting to database at {self.host}:{self.port}...")
        self.connection = {"status": "connected", "data": []} # Simulate a connection object
        return self.connection  # This value is assigned to the 'as' variable
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        """Release the resource."""
        print("Closing database connection...")
        # Here you would close the actual connection
        self.connection = None
        
        # exc_type, exc_val, and exc_tb will be None if no exception occurred.
        if exc_type is not None:
            print(f"An exception occurred: {exc_type.__name__}: {exc_val}")
        
        # Return False (or any falsy value) to propagate the exception.
        # Return True to suppress the exception.
        return False

# Usage:
with DatabaseConnection('localhost', 5432) as conn:
    print(f"Connection status: {conn['status']}")
    conn['data'].append("some data")
    # The connection will be closed automatically when this block is exited.

3. Creating a Function-Based Context Manager

For simpler cases, the @contextmanager decorator from the contextlib module provides a more concise way to create a context manager using a generator function.

from contextlib import contextmanager
import time

@contextmanager
def timer(label: str):
    """A simple context manager to measure the execution time of a code block."""
    start_time = time.perf_counter()
    try:
        # The 'yield' is where the code inside the 'with' block will run.
        yield
    finally:
        # This code runs after the 'with' block is finished.
        end_time = time.perf_counter()
        print(f"{label}: {end_time - start_time:.4f} seconds")

# Usage:
with timer("Data processing task"):
    # Simulate some work
    time.sleep(0.5)
    _ = [i**2 for i in range(100000)]

# Output will be similar to:
# Data processing task: 0.5084 seconds

4. Handling Multiple Contexts

You can manage multiple context managers in a single with statement, which is cleaner than nesting them.

# The modern way (Python 3+)
with open('input.txt', 'r') as infile, open('output.txt', 'w') as outfile:
    content = infile.read()
    outfile.write(content.upper())

# For a dynamic number of contexts, use contextlib.ExitStack
from contextlib import ExitStack

def process_files(filenames):
    with ExitStack() as stack:
        # Enter the context for each file and keep track of the file objects
        files = [stack.enter_context(open(fname, 'r')) for fname in filenames]
        
        # Process all open files
        for f in files:
            print(f"--- Reading from {f.name} ---")
            print(f.readline().strip())
        
        # All files are automatically closed when the ExitStack is exited.

5. Asynchronous Context Managers (Python 3.7+)

For use with async/await, you can create asynchronous context managers using async with. These are defined with __aenter__ and __aexit__ methods.

import asyncio

class AsyncDatabase:
    async def __aenter__(self):
        print("Connecting to async database...")
        await asyncio.sleep(0.1) # Simulate async I/O
        print("Connected.")
        return self
    
    async def __aexit__(self, exc_type, exc_val, exc_tb):
        print("Disconnecting from async database...")
        await asyncio.sleep(0.1) # Simulate async I/O
        print("Disconnected.")
    
    async def query(self, sql):
        await asyncio.sleep(0.2)
        return f"Results for query: '{sql}'"

async def main():
    async with AsyncDatabase() as db:
        result = await db.query("SELECT * FROM users")
        print(result)

asyncio.run(main())
Best Practice: Use @contextmanager for simple, synchronous context managers and a class for more complex ones (e.g., those that manage state). For async code, use @asynccontextmanager or a class with __aenter__/__aexit__.
