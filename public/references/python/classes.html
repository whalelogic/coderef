Python Classes & Object-Oriented Programming

A guide to Python's object-oriented features, including classes, inheritance, decorators, and dunder methods.

Object-Oriented Programming (OOP) is a programming paradigm based on the concept of "objects", which can contain data in the form of fields (often known as attributes or properties) and code in the form of procedures (often known as methods). In Python, everything is an object, and classes are the blueprints for creating these objects.

1. Class Basics

A class is a blueprint for creating objects. It bundles data (attributes) and methods (functions) that operate on the data into a single unit.

Defining a Class

Here is a basic example of a Dog class that demonstrates core concepts like attributes, instance methods, class methods, and static methods.

class Dog:
    # Class attribute: shared by all instances of the class
    species = "Canis familiaris"
    population = 0

    # The __init__ method is the constructor, called when a new object is created.
    def __init__(self, name, age, breed="Mixed"):
        # Instance attributes: specific to each object instance
        self.name = name
        self.age = age
        self.breed = breed
        Dog.population += 1   # Modify the class attribute

    # Instance method: operates on the instance (self)
    def description(self):
        return f"{self.name} is {self.age} years old"

    def speak(self, sound):
        return f"{self.name} says {sound}"

    # Class method: operates on the class itself (cls)
    @classmethod
    def get_population(cls):
        return f"There are {cls.population} dogs."

    # Static method: does not operate on the instance or class. It's like a regular function namespaced within the class.
    @staticmethod
    def is_valid_age(age):
        return 0 <= age <= 30

# Creating instances (objects) of the Dog class
buddy = Dog("Buddy", 5, "Golden Retriever")
max_dog = Dog("Max", 3)

print(buddy.description())      # Output: Buddy is 5 years old
print(buddy.speak("Woof"))      # Output: Buddy says Woof
print(Dog.get_population())     # Output: There are 2 dogs.
print(Dog.is_valid_age(25))     # Output: True

2. Inheritance & Polymorphism

Inheritance allows a class (the child class) to inherit attributes and methods from another class (the parent class). This promotes code reuse.

Single Inheritance

Polymorphism allows us to use a single interface (like the .speak() method) for different types of objects.

class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        raise NotImplementedError("Subclass must implement this abstract method")

class Dog(Animal):
    # This overrides the parent's speak method
    def speak(self):
        return f"{self.name} says Woof!"

class Cat(Animal):
    # This also overrides the parent's speak method
    def speak(self):
        return f"{self.name} says Meow!"

# Polymorphism: we can treat Dog and Cat objects as Animal objects
animals = [Dog("Buddy"), Cat("Whiskers")]
for animal in animals:
    print(animal.speak())
# Output:
# Buddy says Woof!
# Whiskers says Meow!

Multiple Inheritance & MRO

A class can inherit from multiple parent classes. Python determines which method to call using the Method Resolution Order (MRO).

class Flyer:
    def fly(self):
        return "Flying through the air"

class Swimmer:
    def swim(self):
        return "Swimming in water"

# Duck inherits from both Flyer and Swimmer
class Duck(Flyer, Swimmer):
    def quack(self):
        return "Quack!"

duck = Duck()
print(duck.fly())    # From Flyer
print(duck.swim())   # From Swimmer

# The MRO defines the search order for methods: Duck -> Flyer -> Swimmer -> object
print(Duck.__mro__)
# Output: (, , , )

3. Special Methods (Dunder Methods)

Special methods, often called "dunder" (double underscore) methods, allow your objects to integrate with Python's built-in syntax and features, like the len() function or the + operator.

class Book:
    def __init__(self, title, author, pages):
        self.title = title
        self.author = author
        self.pages = pages

    # __str__ provides a user-friendly string representation
    def __str__(self):
        return f'"{self.title}" by {self.author}'

    # __repr__ provides a developer-friendly, unambiguous string representation
    def __repr__(self):
        return f"Book('{self.title}', '{self.author}', {self.pages})"

    # __len__ allows the len() function to be called on an instance
    def __len__(self):
        return self.pages

book = Book("1984", "George Orwell", 328)

print(str(book))  # "1984" by George Orwell
print(repr(book)) # Book('1984', 'George Orwell', 328)
print(len(book))  # 328

4. Properties & Descriptors

Properties allow you to expose "public" attributes while having "private" logic for getting, setting, or deleting their values.

The `@property` Decorator

This is the most Pythonic way to create managed attributes.

class Temperature:
    def __init__(self, celsius):
        # The underscore suggests this is a "private" attribute
        self._celsius = celsius

    @property
    def celsius(self):
        """Getter: Returns the temperature in Celsius."""
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        """Setter: Validates the value before setting."""
        if value < -273.15:
            raise ValueError("Temperature below absolute zero is not possible.")
        self._celsius = value

    @property
    def fahrenheit(self):
        """A computed property derived from celsius."""
        return self._celsius * 9/5 + 32

temp = Temperature(25)
print(temp.celsius)      # 25 (calls the getter)
print(temp.fahrenheit)   # 77.0 (computed on the fly)

temp.celsius = 30        # calls the setter
print(temp.fahrenheit)   # 86.0

5. Dataclasses (Python 3.7+)

The @dataclass decorator automatically generates special methods like __init__(), __repr__(), and __eq__() for you, reducing boilerplate code for classes that primarily store data.

from dataclasses import dataclass, field
from typing import List

@dataclass
class Product:
    name: str
    price: float
    quantity: int = 0
    # Use default_factory for mutable default values like lists or dicts
    tags: List[str] = field(default_factory=list)

    def total_cost(self) -> float:
        return self.price * self.quantity

# The dataclass decorator automatically created the __init__ and __repr__ methods
product = Product("Laptop", 999.99, 5, ["electronics", "computer"])
print(product)
# Output: Product(name='Laptop', price=999.99, quantity=5, tags=['electronics', 'computer'])

print(f"Total cost: ${product.total_cost():.2f}") # Total cost: $4999.95
Best Practice: Use @dataclass for classes that are primarily used to store data. It makes your code more concise and less error-prone. For immutable data containers, use @dataclass(frozen=True).
