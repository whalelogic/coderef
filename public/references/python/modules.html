Python Modules & Packages

A guide to organizing, importing, and distributing code with Python's module and package system.

Modules and packages are the cornerstone of code organization and reusability in Python. A module is a single file of Python code, while a package is a directory of modules that are grouped together.

1. Module Basics

A module is simply a file containing Python definitions and statements. The file name is the module name with the .py suffix. This allows you to logically organize your code and reuse it across different programs.

Creating and Using a Module

To create a module, you save your code in a file with a .py extension.

File: `my_module.py`

"""A simple demonstration module."""

PI = 3.14159

def greet(name: str) -> None:
    """Prints a greeting message."""
    print(f"Hello, {name}!")

def calculate_area(radius: float) -> float:
    """Calculates the area of a circle."""
    return PI * radius ** 2

To use this module in another file (e.g., `main.py`), you use the import statement.

File: `main.py`

# Import the entire module
import my_module

my_module.greet("Alice")  # Output: Hello, Alice!

area = my_module.calculate_area(5)
print(f"The area is: {area}") # Output: The area is: 78.53975

print(f"The value of PI is: {my_module.PI}") # Output: The value of PI is: 3.14159

Import Variations

Python provides several ways to import code, each with its own use case.

# 1. Import the entire module (preferred for clarity)
import math
print(math.sqrt(16)) # 4.0

# 2. Import specific items from a module
from math import sqrt, pi
print(sqrt(16)) # 4.0
print(pi)       # 3.14159...

# 3. Import with an alias to shorten the name
import numpy as np
arr = np.array([1, 2, 3])

# 4. Import everything (NOT RECOMMENDED)
# This pollutes the global namespace and makes it hard to know where functions come from.
from math import *
print(cos(pi)) # -1.0

2. The `if __name__ == "__main__"` Guard

This is a common and important idiom in Python. The code inside this block will only run when the module is executed as a standalone script, not when it is imported into another module. This allows a module to provide both reusable functions and a command-line interface.

# File: my_script.py

def helper_function():
    print("This is a helper function.")

def main():
    print("This is the main function of the script.")
    helper_function()

# This code runs only when you execute `python my_script.py`
if __name__ == "__main__":
    main()

3. Packages

Packages are a way of structuring Python's module namespace by using "dotted module names". A package is a directory of Python modules that contains a special __init__.py file. This file can be empty, or it can contain initialization code for the package.

Example Package Structure


my_app/
├── __init__.py
├── core/
│   ├── __init__.py
│   └── logic.py
└── utils/
    ├── __init__.py
    └── helpers.py

With this structure, you can import modules using dot notation:

from my_app.core import logic
from my_app.utils.helpers import format_data

result = logic.process_data()
formatted = format_data(result)

The `__init__.py` File

The __init__.py file serves two main purposes:

  1. It tells Python that the directory should be treated as a package.
  2. It can be used to expose a public API for the package or run initialization code.
# In my_app/core/__init__.py

# This makes the process_data function available directly from the core package
from .logic import process_data

print("Core package initialized.")

# Now you can import directly from 'core'
from my_app.core import process_data

result = process_data()

4. Dynamic Imports

The importlib module allows you to import modules dynamically using their string names. This is useful for building plugin systems or when the module to be imported is not known until runtime.

import importlib

module_name = "math"
math_module = importlib.import_module(module_name)

print(math_module.sqrt(25)) # 5.0

5. Best Practices

  • Use explicit imports: Write import my_module and use my_module.my_function(). This makes code readable and avoids namespace conflicts.
  • Avoid from module import *: It pollutes your namespace and makes it difficult to trace the origin of functions and variables.
  • Group and order imports: Follow the standard convention:
    1. Standard library imports (e.g., os, sys)
    2. Third-party library imports (e.g., numpy, requests)
    3. Local application/library imports
  • Use absolute imports by default: from my_app.core import logic is clearer than relative imports, especially in complex projects.
  • Use the if __name__ == "__main__" guard to separate reusable logic from script-specific execution code.
