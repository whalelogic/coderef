Python Exception Handling

A guide to handling errors and exceptions gracefully using `try`, `except`, `else`, and `finally`.

Exception handling is a critical part of writing robust and reliable Python code. It allows you to manage errors and exceptional situations without crashing your program.

1. The `try...except` Block

The core of exception handling is the try...except block. Python places code that might raise an exception inside the try block. If an error occurs, the code inside the except block is executed.

try:
    # Code that might cause an error
    numerator = 10
    denominator = 0
    result = numerator / denominator
    print(result)
except ZeroDivisionError:
    # Code that runs if a ZeroDivisionError occurs
    print("Error: Cannot divide by zero!")

print("Execution continues after the try...except block.")

Handling Multiple Exceptions

You can handle different types of exceptions in different ways by adding more except blocks.

my_dict = {"a": 1, "b": 2}

try:
    value = my_dict["c"]
    result = 10 / 0
except KeyError:
    print("Error: That key does not exist in the dictionary.")
except ZeroDivisionError:
    print("Error: Cannot divide by zero.")

# You can also handle multiple exceptions in a single block
try:
    # ... some code ...
    pass
except (KeyError, IndexError) as e:
    print(f"A lookup error occurred: {e}")

2. The `else` and `finally` Clauses

The try...except block can be extended with optional else and finally clauses.

  • The else block runs only if no exceptions were raised in the try block.
  • The finally block runs no matter what, whether an exception occurred or not. It is typically used for cleanup actions.
def divide(a, b):
    try:
        result = a / b
    except ZeroDivisionError:
        print("Error: Division by zero is not allowed.")
    else:
        # This runs only if the division was successful
        print(f"Result is {result}")
    finally:
        # This runs every time, regardless of an exception
        print("Division operation finished.")

divide(10, 2)
print("-" * 20)
divide(10, 0)

3. Raising Exceptions

You can raise your own exceptions using the raise keyword. This is useful when a certain condition is not met in your code.

def set_age(age):
    if age < 0:
        # Raise an exception if the age is invalid
        raise ValueError("Age cannot be negative.")
    print(f"Age set to {age}")

try:
    set_age(25)
    set_age(-5)
except ValueError as e:
    print(f"Error setting age: {e}")

4. Custom Exceptions

For more specific error handling, you can create your own custom exception classes by inheriting from Python's base Exception class. This makes your code more readable and allows you to catch specific errors related to your application's logic.

# Define a custom exception class
class InsufficientFundsError(Exception):
    """Raised when a withdrawal amount exceeds the account balance."""
    pass

class BankAccount:
    def __init__(self, balance):
        self.balance = balance

    def withdraw(self, amount):
        if amount > self.balance:
            # Raise the custom exception
            raise InsufficientFundsError(f"Cannot withdraw ${amount}, only ${self.balance} available.")
        self.balance -= amount
        return self.balance

account = BankAccount(100)
try:
    account.withdraw(50)
    print(f"New balance: ${account.balance}")
    account.withdraw(80) # This will raise the custom exception
except InsufficientFundsError as e:
    print(f"Transaction failed: {e}")
Best Practice: Creating custom exceptions makes your error handling more specific and your program's intent clearer. It's better to catch a specific InsufficientFundsError than a generic Exception.

5. Best Practices for Exception Handling

  • Be specific in your except blocks. Avoid catching the base Exception class, as it can hide bugs. Catch the specific errors you expect.
  • Don't suppress exceptions silently. Unless you have a very good reason, don't use a bare except: pass. At a minimum, log the error.
  • Use finally for cleanup. Ensure that resources like files or network connections are closed, regardless of whether an error occurred.
  • Create custom exceptions for your application. This makes your error-handling logic more robust and easier to understand.
  • Keep try blocks small. Only wrap the specific lines of code that might raise an exception.
